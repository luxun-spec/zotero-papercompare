# PaperCompare 初版设计

日期：2026-10-16
状态：已获用户批准，初版已实现；实际验证与已知边界见 docs/verification.md。

## 目标与范围

为 Zotero 10 创建免费、离线使用的插件，帮助用户人工摘录原文证据、整理并比较多篇论文。初期以 Windows 上的 Zotero 10.0.1 为实际验证环境。项目暂名 PaperCompare；标识暂用 papercompare@local.research，发布前检查名称冲突。

采用“先创建对比表，再阅读填写”的流程。提供通用、自定义字段及 AI Infra 模板。每行对应一篇论文的一组实验；同一论文可以有多行。默认以实验条件和结果的实际记录为准，不自动推断公平性。

## 用户操作

1. 文库菜单增加 PaperCompare 入口，打开独立对比窗口。
2. 创建、重命名、删除对比表；删除必须确认，并支持导出备份。
3. 从当前选中的顶层文献条目加入论文；附件选择归一到父条目，无父条目的附件提示先关联文献。
4. 自定义字段名称、添加字段及移除字段。移除已有内容的字段需要确认。
5. 为论文添加具名实验行。在单元格编辑整理后的值。
6. 阅读 PDF 时先创建 Zotero 原生文本高亮，再在插件证据选择器中选择该论文的批注，关联到指定单元格。一个单元格支持多条证据。第一版复用已保存的原生批注，后续再增加即时选中文本入口。
7. 点击证据，跳回对应 PDF 批注。失效的附件或批注显示清晰提示，保留已有摘录和整理值。
8. 导出 Markdown、CSV 和可恢复的 JSON 备份；支持导入本插件 JSON 备份并校验结构，新建对比表而不覆盖原表。

## 界面

独立窗口左侧列出对比表，右侧显示表名、字段管理和表格。表格固定显示论文、实验名称，其后为自定义字段。选中单元格时下方显示整理值编辑区与证据列表。证据展示原文、PDF 页码标签、作者与年份（可用时），提供“定位原文”和“解除关联”。

界面支持简体中文和英文；默认跟随 Zotero 语言。表格支持横向滚动、键盘访问、暗色模式与长文本换行。

## 内置模板

通用：研究问题、方法、数据集、主要结果、局限。
AI Infra：模型、GPU 配置、数值精度、数据集/工作负载、输入长度、输出长度、吞吐量、延迟、其他条件。

数值和单位保留为用户可编辑文本；不擅自换算或把不同指标合并。空单元格表示尚未记录，不等同于论文未报告。

## 数据模型与存储

使用 Zotero 数据目录下独立的 PaperCompare JSON 文件，不直接写 Zotero SQLite 数据库，不改写论文元数据或原生批注。

文件带 schemaVersion。对比表包含 UUID、名称、字段、实验行和时间戳；实验行记录 Zotero libraryID 与 itemKey；单元格记录整理值和证据列表。证据包含 attachmentKey、annotationKey、原文快照、页码标签和批注位置快照。位置数据来自 Zotero 原生批注。

先成功保存再显示成功状态。保存操作串行执行，使用临时文件与原子替换；保留上一份有效备份。首次读取失败时停止写入，提示恢复备份，禁止静默以空文件覆盖。跨设备同步与多人协作不在本版范围；JSON 导入导出用于手工迁移。

## 技术结构

TypeScript 编写，构建为带 manifest.json、bootstrap.js 和界面资源的 XPI。生命周期负责注册与清理菜单、窗口和监听器。纯数据模型、校验、导入导出与 UI/Zotero 适配分离。依赖和模板来源、许可证在实现计划中明确核对，不直接复制不明许可代码。

源码使用 git 管理，提供 README 中英文说明、许可证、构建步骤、演示用合成数据及 GitHub Actions 构建检查。用户文库、真实 PDF、密钥和本地路径不提交。GitHub 创建远程仓库及推送在初版验证后执行。

## 验收

- 安装、启用、禁用和重新启用插件无重复菜单或残留窗口。
- 创建表、加入至少两篇论文、建立多实验行、修改字段及值；重启后内容保持。
- 单元格关联至少两条 PDF 高亮证据，定位原文成功。
- 缺失原批注时仍显示快照并提示无法定位。
- Markdown 与 CSV 导出正确处理中文、引号、逗号、换行及潜在电子表格公式字符。
- JSON 备份导入后内容完整，非法版本/损坏文件被拒绝且原数据不变。
- 模拟写入失败时不报告已保存、不损坏原文件。
- 在隔离的 Zotero 测试配置中先验证，再安装到日常配置；真实文库中不为测试创建或删除条目。

## 明确限制

不包含 AI/API、自动论文总结、全文机器翻译、OCR、自动提取图表数值、自动评判可比性或云同步。证据跳转依赖 Zotero 中的原附件和原批注仍存在。GitHub Star 数量不作为交付保证。
